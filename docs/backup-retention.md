# 백업 최신본 관리(보존 정책)

서버 볼륨의 DB 백업이 무한정 쌓이지 않도록, **최신 검증된 1세트만 남기고 이전 백업은 내용이 완전히 보존된 경우에만** 지우는 정책입니다. 기본값은 **꺼짐**이며, 배포만으로는 아무것도 지워지지 않습니다.

> 이 문서는 코드가 하는 일을 설명합니다. 코드가 병합·배포되고 아래 ‘켜는 방법’이 적용되기 전에는 운영에서 아무 일도 하지 않습니다.

## 무엇을 보존하는가

| 대상 | 규칙 |
|---|---|
| 운영 DB(`prod.db`)와 WAL·SHM·journal | 이 코드는 읽기 전용으로만 열며 수정·삭제하지 않음 |
| 참여자 응답 RAW | 어떤 단계에서도 삭제·수정하지 않음. 아래 ‘비교 범위’의 모든 표의 모든 행·열 값이 보존 사본에 있어야 이전 백업을 지움 |
| 조사 완료 RAW 기준본 | 정책 파일의 `rawBaseline`. 자동 교체·삭제 대상에서 제외(전화번호 정비 전 값 등 이 사본에만 있는 값을 보존) |
| 최신 전체 백업 1세트 | DB + `manifest.json` + `analysis-packages/`(ZIP 하드링크). 새 세트가 검증된 뒤에만 이전 세트가 후보가 됨 |
| 등록된 분석 ZIP | 라이브 `analysis-packages/`의 파일은 지우지 않음(백업 안의 ZIP은 같은 파일의 하드링크라 백업 폴더를 지워도 파일은 남음) |
| 자동 백업 이름(`YYYYMMDDTHHMMSSZ_이유`)이 아닌 폴더 | `changelog/`, `survey-complete_…`, `pre-mds-v2_…` 등은 후보가 되지 않음 |

## 비교 범위(어떤 표·파일을 보는가)

실제 운영 최신 백업(2026-10-23 사본)의 표 13개를 전부 대조한 결과입니다. Prisma 스키마의 모델 12개 + 마이그레이션 이력 1개와 일치합니다.

| 구분 | 표 | 처리 |
|---|---|---|
| RAW | `Project`, `Statement`, `SortSession`, `SortGroup`, `SortGroupItem` | **비교**(모든 행·모든 열) |
| 파생 결과 | `AnalysisRun`, `AnalysisRunDimension`, `AnalysisInterpretation`, `AnalysisClusterLabel`, `AnalysisPackage` | **비교**(모든 행·모든 열) |
| 목록에 없는 표 | (현재 없음) 나중에 스키마에 추가되는 표 | **기본적으로 비교**. 목록에 이름이 없어도 빠지지 않음 |
| 운영 작업 상태 | `AnalysisPackageJob`, `AnalysisExecutionLock` | 비교 제외(연구 자료 아님, 진행 상태일 뿐) |
| 마이그레이션 이력 | `_prisma_migrations` | 비교 제외(백업 검증 단계에서 별도 확인) |

파일 범위: 후보가 되는 것은 자동 백업 이름 폴더뿐입니다. `changelog/`(전화번호 정비 전·후 기록), RAW 기준본 폴더, `pre-mds-v2_…`, 정책 파일, `status.json`, `backup-log.jsonl`은 후보가 아니라 그대로 둡니다. 라이브 ZIP·DB·WAL·SHM은 어떤 경우에도 대상이 아닙니다.

### 삭제를 막는 조건(하나라도 해당하면 그 백업을 지우지 않음, 계획 전체가 막히는 경우도 있음)

| 조건 | 결과 |
|---|---|
| 후보의 어떤 표에든 최신본·기준본 어디에도 같은 값으로 없는 행이 있음(값 하나만 달라도) | 해당 백업 보존(`RAW_ROWS_ONLY_IN_THIS_BACKUP` / `RESULT_ROWS_ONLY_IN_THIS_BACKUP`) |
| 후보에는 있는데 최신본·기준본에 **표나 열이 없음** | 그 사본은 값을 보증하지 못함 → 보존 |
| 후보 자체가 검증되지 않음(SHA-256, 무결성, ZIP 해시, 매니페스트가 가리키는 파일 경로가 백업 밖) | 보존(`CANDIDATE_NOT_VERIFIED`) |
| 후보의 ZIP 중 최신본에 없는 것이 있음 | 보존 |
| 비교 중 오류 | 보존(`COMPARISON_FAILED`) |
| 최신본이 검증되지 않음, 기준본이 검증되지 않음, 기준본과 최신본이 같음 | 전체 중단 |
| **검증 기록 불일치**: `status.json`에 기록된 최신 백업 이름·SHA-256·내용 지문이 실제 최신본과 다름 | 전체 중단(`LATEST_RECORD_MISMATCH`) |
| 최신본에 알려진 RAW 표가 없음 | 전체 중단(`LATEST_MISSING_RAW_TABLE`) |
| 최신본의 RAW·미등록 표 행이 라이브 DB에 같은 값으로 없음 | 전체 중단(`LATEST_RAW_NOT_IN_LIVE`) |
| 정책 파일 없음·형식 오류·읽기 불가, 환경 변수 꺼짐 | 아무것도 지우지 않음 |

180쌍(후보 15개 × 표 12개)의 파이썬·자바스크립트 비교 일치는 **서로 다른 두 구현이 같은 결론을 낸다는 교차 확인일 뿐**, 구현 자체가 옳다는 증명이 아닙니다. 두 구현이 같은 잘못된 가정을 공유할 수 있으므로 변이 시험(조건을 일부러 망가뜨려 시험이 실패하는지)을 함께 합니다.

## 생성 → 검증 → 확정 → 정리 순서

1. 임시 폴더 `.tmp-*`에 DB 스냅샷·`manifest.json`·ZIP 링크를 **모두** 만들고 그 안에서 검증(SHA-256, `integrity_check`, ZIP 해시, 마이그레이션 이력).
2. 검증을 통과하면 이름 변경(rename) 한 번으로 확정. 같은 이름이 이미 있으면 덮어쓰지 않고 실패. 실패하면 임시 폴더를 지우고 기존 백업은 그대로.
3. 최신본이 `status.json`의 기록과 일치하는지, RAW 표가 모두 있는지, 그 행이 라이브 DB에 모두 들어 있는지 확인(백업 후 추가된 응답은 허용, 값이 바뀐 행이 있으면 정리를 건너뜀).
4. 정책 파일의 기준본이 검증되는지 확인.
5. 이전 백업마다 위 ‘막는 조건’을 확인하고, 모두 통과한 것만 삭제 후보로 확정.
6. 삭제는 실행 직전에 보호 규칙·경로(진짜 디렉터리, 링크 아님, 백업 폴더 바로 아래)를 다시 확인한 뒤 **`.deleting-<이름>`으로 이름 변경 한 번**으로 백업 목록에서 빼고, 그다음 그 폴더를 지운다(링크는 따라가지 않음). 이름 변경이 실패하면(권한 등) 백업은 온전한 채 남고 오류가 기록된다. 지우는 도중 실패하거나 프로세스가 중단돼도 ‘반쯤 지워진 백업’이 백업 이름으로 남지 않고, 남은 `.deleting-*`는 다음 실행에서 마저 지운다.

어떤 단계든 오류·불일치·애매함이 있으면 **모든 기존 백업을 그대로 둔다**. 동시 실행은 `.backup.lock`(배타적 생성)으로 막고, 30분이 지난 잠금은 인계. 한 시간 넘은 `.tmp-*`는 다음 실행 때 지워 임시 사본이 쌓이지 않게 한다. 데이터가 바뀌지 않으면 백업을 건너뛰는 기존 동작과 6시간 점검 주기는 그대로입니다.

## 켜는 방법(두 가지가 모두 있어야 삭제됨)

1. 서버의 백업 폴더(`/data/backups/`)에 `retention-policy.json`을 만든다.

```json
{ "version": 1, "rawBaseline": "survey-complete_20261016T120119Z", "protect": ["pre-mds-v2_20261018T101212Z"] }
```

2. 서비스 환경 변수 `AUTO_BACKUP_RETENTION`을 `dry-run`(계획만 기록) 또는 `apply`(삭제)로 설정한다. 값이 없거나 다르면 꺼짐.

권장 순서: **먼저 `dry-run`** 으로 한 번 이상 돌려 `status.json`의 `lastRetention`(삭제 예정 목록과 보존 사유)과 `backup-log.jsonl`을 확인한 뒤 `apply`로 바꾼다. 수동 점검: `node scripts/backup/retention.mjs --db /data/prod.db --dry-run`(기본) 또는 `--apply`(정책 파일 필요).

결과는 `status.json`의 `lastRetention`과 `backup-log.jsonl`(`RETENTION_DELETED`·`RETENTION_NOT_APPLIED`·`RETENTION_ERRORS`)에 남는다.

## PC의 최신본

서버는 PC를 볼 수 없으므로 ‘PC 최신본’은 서버 코드가 아니라 PC에서 직접 실행하는 스크립트가 표시한다.

```
node scripts/backup/pull-latest-to-pc.mjs --dest <PC 폴더> --service <Railway 서비스 ID> [--prune]
node scripts/backup/pull-latest-to-pc.mjs --dest <PC 폴더> --status
```

PC 폴더에는 서로 다른 두 기록이 있다.

| 파일 | 뜻 |
|---|---|
| `PC_LATEST.json` | **마지막 성공 기록**. 검증이 끝나 확정된 사본의 백업 이름, `manifest.json`의 SHA-256, 모든 파일의 크기·SHA-256, 검증 시각. 성공했을 때만 갱신되고 실패해도 그대로 보존 |
| `PC_SYNC.json` | **현재 동기화 상태**. 실행할 때마다 갱신. `동기화됨` / `동기화 대기` / `확인 불가` + 확인 시각 + 서버 최신본의 이름·해시 |

| 상태 | 언제 |
|---|---|
| `동기화됨` | 서버의 최신 백업(같은 이름, 같은 매니페스트 해시)이 PC에 있고 다시 검증됨 — **확인 시각 기준** |
| `동기화 대기` | 서버 최신본이 아직 PC에 없음(전송·검증 실패, 서버가 검증됨으로 기록하지 않음, 검증 기록 불일치, 같은 이름의 PC 사본이 해시가 다르거나 더 이상 검증되지 않음). PC에 있는 것은 이전 백업 |
| `확인 불가` | 서버에 연결하지 못해 최신본이 PC에 있는지 알 수 없음. 확인 기록이 한 번도 없을 때도 같음 |

- 과거의 성공 기록은 ‘현재 최신본이 PC에 있다’는 근거가 아니다. `동기화됨`만 그것을 말하며 확인 시각까지만 유효하다. `--status`는 서버에 접속하지 않고 이 기록을 보여 주며, 마지막 성공 기록과 현재 상태를 따로 표시한다.
- 서버의 `status.json`이 최신 백업을 검증됨으로 기록하고, 그 SHA-256이 매니페스트와 같을 때만 가져온다. 매니페스트가 백업 폴더 밖의 경로를 가리키면 거부한다.
- 임시 폴더에서 모든 파일의 크기·SHA-256을 서버 `manifest.json`과 대조하고 PC에서 다시 검증(`integrity_check`, ZIP 해시)한 뒤에만 폴더로 확정하고 `PC_LATEST.json`을 갱신한다.
- `--prune`은 새 사본이 검증된 뒤에만, 이 스크립트가 만든(`PC_VERIFIED.json`이 있는) 이전 사본만 지우고 최신 1개를 남긴다. 다른 폴더·파일은 건드리지 않는다.
- **PC가 꺼져 있으면** 서버 쪽 정리는 PC와 무관하게 위 조건(RAW 보존 등)만으로 판단한다. 즉 PC에 없는 백업이라도 내용이 최신본·기준본에 모두 있으면 서버에서 지워질 수 있다. PC에 사본을 반드시 남기고 싶은 백업은 정책 파일 `protect`에 넣는다.

## 시험 상태

| 시험 | 상태 |
|---|---|
| 단위·통합(정상 교체, 생성·검증 실패, RAW 불일치, 미등록 표, 검증 기록 불일치, 경로 이탈, 링크, 이름 변경·삭제 실패(모의 오류), 프로세스 강제 종료, 동시 실행, PC 동기화 상태) | 실시(개발 PC, Windows) |
| Linux 컨테이너에서 같은 시험 | **미실시**(Docker 엔진이 정해 둔 대기 시간 안에 준비되지 않음) |
| 실제 Linux 사용자 권한(읽기 전용 마운트, 다른 사용자 소유 파일)으로 인한 오류 | **미실시**(권한 오류는 오류 주입으로만 시험) |
| 운영 서버에서의 `dry-run`·`apply` | **미실시**(배포·정책 파일·환경 변수 적용 전) |
| 사람의 코드 검토 | **미실시** |

## 한계

- PC 사본은 PC가 연결돼 스크립트를 실행했을 때만 갱신된다(자동 아님).
- 정리는 같은 볼륨 안의 백업만 대상으로 하며, 서버 밖(외부 저장소)에 대한 동작은 없다.
- 이 정책은 파일 용량을 관리할 뿐 불변 보관이 아니다(읽기 전용 속성은 실수 방지용).
- 비교는 값이 같은지만 본다. 학문적 타당성이나 분석 결과의 옳고 그름과는 무관하다.
