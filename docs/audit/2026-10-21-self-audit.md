# 웹앱·산출물 자체 점검 기록 (2026-10-21)

범위: 배포된 웹앱(관리자 분석 화면·API·ZIP 파이프라인·백업)과 연구 산출물(ZIP·Excel·그림). 직접 재현하거나 실행해 확인한 항목만 적었습니다. 시험은 운영이 아니라 운영 DB 사본을 올린 **격리된 Docker 환경**(운영과 같은 이미지·같은 마이그레이션 경로)에서 했습니다. 참여자 응답은 어떤 단계에서도 수정하지 않았습니다.

## 1. 확인된 결함과 수정

## 2. 연구 산출물의 개선(결함이 아닌 품질 향상)

- 그림: 인쇄 폭 16 cm 기준 한 번 렌더링(PNG 600 dpi 3,780 px, SVG, PDF). 기존에는 18.3 cm 폭 300 dpi PNG였음. 번호·윤곽·범례·축·표본 수·범위·버전 표기, 글꼴 누락 시 제작 중단, 사분면 번호 제거(네 사분면을 군집으로 읽을 여지 제거), 잔차 진단과 문항별 stress 기여 그림 추가, 차원별 그림에 RSQ, 군집 수 그림에 군집 간 제곱합 비율·최소 군집 크기 추가, 캡션·주석·대응 데이터 파일을 그림목록에 연결.
- Excel: 한 범위의 모든 표(S·P·D·δ, 좌표·군집, 차원·군집 수별 지표, 문항 쌍 진단, 안정성, 검증, 지표 정의, 참고문헌, 그림 목록, 편집 가능한 차트)를 실제 셀로. 수식은 검산 시트에만 있고 계산 결과값이 저장됨(실제 Excel에서 다시 계산해 일치 확인).
- 보고서(PDF·Word): 같은 캡션·주석 사용, 그림은 용량 때문에 절반 해상도 사본.

## 3. 점검했으나 결함이 없던 항목

- 인증: 관리자 15개 엔드포인트를 토큰 없음·잘못된 토큰·다른 프로젝트 토큰으로 호출 → 모두 401/403. 다른 프로젝트의 slug와 토큰으로 이 프로젝트의 실행·ZIP·번들·작업을 요청 → 404.
- 범위 대응: 한국·일본·전체의 ZIP 매니페스트 실행 ID·범위·세 지문이 번들·개요와 일치(운영과 격리 환경 모두). 국가별 ZIP의 응답은 해당 국가만(검증 스크립트).
- 본조사·파일럿: ZIP 작업은 `dataset=MAIN`인 실행에만 만들어지며(코드), 패키지 검증의 ‘파일럿 행 없음’ 항목 통과.
- 이전 결과와 현재 ZIP: 개요가 다른 실행의 ZIP을 ‘이전 검증 결과’로 따로 표시(운영 개요에서 확인).
- ZIP 작업의 중복 요청·실패 후 ZIP만 재시도·프로세스 중단 후 복구: 직전 단계에서 최종 이미지로 시험 완료(재시도·복구 후에도 분석 실행 행 불변). 이번 단계에서 반복하지 않음.
- 오류가 아닌 ‘확인했으나 바꾸지 않은 것’: 번호 없이 호출 가능한 `GET /api/projects/<slug>/sorts`가 제출 건수만 공개(slug를 알아야 하며 개인정보 없음). 영향이 작아 두었음.

## 5. 최종 검증(원본 크기 그림 점검·Excel 정밀도)에서 추가로 확인한 항목

분석값·좌표·군집 소속은 바꾸지 않았습니다. 수정은 표현과 기록에 한정했고 새 패키지 버전(형식 5)으로만 반영했습니다. 이전 버전은 모두 보존합니다.

| # | 항목 | 확인 방법 | 내용 | 조치 |
|---|---|---|---|---|
| F1 | F14 Procrustes 그림의 문항 번호 겹침 | 원본 PNG를 50% 보기와 원본 크기 잘라보기로 확인 | 개념도에는 있던 겹침 방지 배치가 이 그림에는 없어 가까운 점의 번호(40/10, 41/42, 36/40 등)가 서로 겹침 | 개념도와 같은 배치 함수 사용 |
| F2 | F11 분할 반분 그림의 평균 라벨 | 원본 크기 잘라보기 | 평균 라벨의 흰 반투명 상자가 가장 높은 막대의 윗부분을 가려 막대가 낮아 보임 | 상자 제거, y축 위쪽 여백에 라벨 배치 |
| F3 | F10 차원별 그림의 값 라벨 | 원본 크기 잘라보기 | 점을 잇는 선이 값 라벨의 첫 글자를 가로지름 | 라벨에 흰 테두리 |
| E1 | 좌표 CSV의 정밀도 | Excel의 값과 CSV의 값 비교 | `좌표_2D.csv`가 소수 12자리로 반올림되어 Excel의 값(전체 정밀도)과 최대 약 5e-13 차이. 군집 소속·보고 값에는 영향 없음 | CSV를 전체 정밀도로 저장하고 README에 기준 파일 명시 |
| E2 | 영어 저장값의 표시 | 보고서·Excel 본문 점검 | `random halves`가 지표 표에 그대로 표시 | 표시 문구를 ‘무작위 반분’으로 옮기고 용어 대응표 추가(저장값은 보존) |

Excel 정밀도 단계별 결과(`verify_excel_precision.py`): ① 생성된 XLSX 내부 숫자 ↔ 기준 CSV, ② 실제 Excel에서 열고 `CalculateFull` 한 값, ③ Excel에서 사본으로 저장해 다시 읽은 값. 형식 5의 세 범위 모두 모든 숫자 셀(28,251 / 29,024 / 42,988개)이 ①②③에서 이 검사 방식(IEEE 배정밀도 값의 동등 비교)으로 서로 같았고, ‘표시된 정밀도로 계산’ 옵션은 꺼져 있었으며 오류 셀은 0개입니다. 이는 이 도구와 이 Excel 빌드에서의 측정 결과이며 다른 Excel 버전·옵션에서의 동일성을 주장하지 않습니다.
